## A second lesson on plan-document hygiene, beyond the fence-parity one from the scaffold plan

Two real defects surfaced in THIS plan during implementation so far, both caught by implementers reading the actual codebase rather than blindly following the brief: a systemic partial-DDL bug (Task 7) and a silently-dropped module in a barrel-export rewrite (Task 8). Both are the same underlying failure mode — hand-retyping a list of things (columns, module names) from memory/context rather than copying it verbatim from a known-good source, and silently dropping an entry. When a future plan needs to reproduce a list that already exists correctly elsewhere in the codebase or an earlier task, copy it exactly rather than retyping it from memory.

## Cross-cutting pattern confirmed in this session

The `conn.dialect === 'sqlite'` narrowing requirement — first discovered in the v0.1-alpha scaffold's `apps/web/lib/auth.ts` — has now recurred in every single piece of `packages/core` code that queries the database (Tasks 2 and 3, both). This is no longer a "might happen" risk to flag defensively; it's a confirmed, load-bearing characteristic of this codebase's `SqliteConn | PgConn` design. Every remaining task whose brief includes a `conn.db` query (Task 7's pipeline persistence, and the web routes in Tasks 12-14) should expect to need it and should not be surprised when the brief's literal unnarrowed reference code fails typecheck. Tasks 4-6 (the providers) don't touch the database at all, so this doesn't apply to them.
