# NetPro v0.1-alpha Scaffold Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the NetPro monorepo scaffold — a buildable, lintable, typecheckable, testable skeleton for `apps/web` (Next.js) and `apps/cli` (commander), backed by shared `packages/core`, `packages/db`, `packages/ui`, `packages/config`, with no real feature logic yet.

**Architecture:** npm workspaces + Turborepo monorepo. Two dual-dialect Drizzle schemas (SQLite for CLI/local, Postgres for hosted web) selected at runtime via `DB_DIALECT`. Auth.js v5 with a GitHub OAuth provider gates the web app's protected routes. The CLI is a commander program with seven stub subcommands and an encrypted-file credential store (no OS keychain yet). Every route/command exists as a real, working file — placeholder content only, no business logic.

**Tech Stack:** TypeScript (strict), Next.js (latest stable, App Router), React (latest stable), Auth.js v5 (`next-auth@beta`) + `@auth/drizzle-adapter`, Drizzle ORM + drizzle-kit, better-sqlite3, pg, Tailwind CSS v3 + shadcn/ui pattern, commander, tsup, Vitest, Turborepo, npm workspaces, Docker.

## Global Constraints

- Node engines `>=20` (installed runtime: v24.14.1) — declared in the root `package.json` and in the two publishable/executable apps (`apps/cli`, `apps/web`). Internal library packages under `packages/*` (`config`, `db`, `core`, `ui`) are never installed standalone outside this workspace, so they don't repeat the field — clarified after Task 5's review caught that Tasks 2 and 4's package templates already omitted it too, consistent with this scoping.
- Package manager: **npm workspaces**, not pnpm. Root `package.json` has a `"workspaces"` array; every dependency install for an app/package uses `npm install -w <workspace-path> <packages>` from the repo root so npm resolves and pins real current versions — never hand-write version numbers into `package.json`.
- TypeScript strict mode everywhere, via a single shared `tsconfig.base.json` at the repo root (each app/package extends it with a relative path).
- TypeScript is pinned to `^5` (latest 5.x line) in every install — discovered during Task 2's review that `typescript-eslint` hard-refuses to run under TypeScript 7.x (npm's unpinned resolution picked up 7.0.2 in Task 1, which broke ESLint entirely). This is a deliberate, disclosed exception to "never hand-write version numbers" — the other is `commander`, pinned to `^14` in Task 7 (Step 10) because `commander@15` requires Node `>=22.12`, conflicting with this project's `>=20` floor. Any future task that hits a similar version-floor conflict should pin the same way and add itself to this list.
- Database: Drizzle ORM, **two parallel schema files** (`schema.sqlite.ts`, `schema.pg.ts`) — Drizzle does not support one dialect-agnostic schema file across sqlite/postgres column types, so this plan deviates from the design doc's single `schema.ts` mention and uses the standard two-file pattern instead. Dialect selected at runtime via `DB_DIALECT` env var (`sqlite` default, `postgresql` optional).
- No SQLCipher, no `keytar`/OS-keychain, no Playwright/E2E, no rate limiting, no CSRF tokens, no audit logging, no KeyVault encryption, no RLS policies in this pass — all deferred per the approved design spec.
- Tailwind CSS v3 (JS config) instead of the design spec's "v4" — v4's CSS-first config path is still a moving target and shadcn/ui's well-documented setup path is against v3; noted here as a deliberate, disclosed deviation for scaffold reliability.
- The design spec's `packages/config/tsconfig/base.json` is dropped in favor of a single root `tsconfig.base.json` (avoids a duplicate/ambiguous second base config); `packages/config` holds only the shared ESLint and Tailwind presets.
- `packages/core`, `packages/db`, `packages/ui` are consumed as TypeScript source directly (no separate build/bundle step) — Next.js's `transpilePackages` and tsup's `noExternal` handle this. Their `"build"` script is `tsc --noEmit`, acting as the build gate.
- MIT license, copyright holder "NetPro Contributors".
- Every task ends with `git add` + `git commit` for exactly the files that task created or modified.
- The blueprint's own Security doc assumes a `users`/`accounts`/`sessions`/`verificationTokens` table set for Auth.js's `DrizzleAdapter`, but the DB blueprint's schema never defines them — Task 10 adds the standard `@auth/drizzle-adapter` table shapes to both schema files to close this gap. `contacts.ownerId`/RLS multi-tenancy wiring stays deferred, matching the design spec.

```ts
// packages/db/src/index.ts
import Database from 'better-sqlite3';
import { drizzle as drizzleSqlite, type BetterSQLite3Database } from 'drizzle-orm/better-sqlite3';
import { drizzle as drizzlePg, type NodePgDatabase } from 'drizzle-orm/node-postgres';
import { Pool } from 'pg';
import * as sqliteSchema from './schema.sqlite';
import * as pgSchema from './schema.pg';

export * as sqliteSchema from './schema.sqlite';
export * as pgSchema from './schema.pg';

export type SqliteConn = {
  dialect: 'sqlite';
  db: BetterSQLite3Database<typeof sqliteSchema>;
  schema: typeof sqliteSchema;
};

export type PgConn = {
  dialect: 'postgresql';
  db: NodePgDatabase<typeof pgSchema>;
  schema: typeof pgSchema;
};

function resolveDialect(): 'sqlite' | 'postgresql' {
  const dialect = process.env.DB_DIALECT ?? 'sqlite';
  if (dialect !== 'sqlite' && dialect !== 'postgresql') {
    throw new Error(`Unknown DB_DIALECT "${dialect}". Expected "sqlite" or "postgresql".`);
  }
  return dialect;
}

export function createDb(): SqliteConn | PgConn {
  const dialect = resolveDialect();

  if (dialect === 'sqlite') {
    const path = process.env.DB_PATH ?? './netpro.db';
    const sqlite = new Database(path);
    return { dialect, db: drizzleSqlite(sqlite, { schema: sqliteSchema }), schema: sqliteSchema };
  }

  const connectionString = process.env.DATABASE_URL;
  if (!connectionString) {
    throw new Error('DATABASE_URL is required when DB_DIALECT=postgresql');
  }
  const pool = new Pool({ connectionString });
  return { dialect, db: drizzlePg(pool, { schema: pgSchema }), schema: pgSchema };
}
```

```ts
// apps/cli/src/config/keychain.ts
import { createCipheriv, createDecipheriv, randomBytes, scrypt } from 'node:crypto';
import { promisify } from 'node:util';
import { existsSync, mkdirSync, readFileSync, writeFileSync } from 'node:fs';
import { homedir, hostname } from 'node:os';
import { join } from 'node:path';

const scryptAsync = promisify(scrypt);

function getConfigDir(): string {
  const dir = join(homedir(), '.netpro');
  if (!existsSync(dir)) mkdirSync(dir, { recursive: true });
  return dir;
}

async function getMasterKey(): Promise<Buffer> {
  // Machine-specific key derivation. Swapping this for a real OS keychain
  // (keytar or a maintained successor) is tracked as follow-up work — see
  // the design spec's "CLI secrets" deviation.
  return (await scryptAsync(hostname(), 'netpro-salt-v1', 32)) as Buffer;
}

export class Keychain {
  private static get fallbackPath(): string {
    return join(getConfigDir(), 'credentials.enc');
  }

  static async set(key: string, value: string): Promise<void> {
    const store = await this.loadStore();
    store[key] = value;
    await this.saveStore(store);
  }

  static async get(key: string): Promise<string | null> {
    const store = await this.loadStore();
    return store[key] ?? null;
  }

  static async delete(key: string): Promise<void> {
    const store = await this.loadStore();
    delete store[key];
    await this.saveStore(store);
  }

  static async listKeys(): Promise<string[]> {
    return Object.keys(await this.loadStore());
  }

  private static async loadStore(): Promise<Record<string, string>> {
    if (!existsSync(this.fallbackPath)) return {};

    const masterKey = await getMasterKey();
    const encrypted = readFileSync(this.fallbackPath);

    const iv = encrypted.subarray(0, 16);
    const authTag = encrypted.subarray(encrypted.length - 16);
    const ciphertext = encrypted.subarray(16, encrypted.length - 16);

    const decipher = createDecipheriv('aes-256-gcm', masterKey, iv);
    decipher.setAuthTag(authTag);

    const decrypted = Buffer.concat([decipher.update(ciphertext), decipher.final()]);
    return JSON.parse(decrypted.toString('utf-8'));
  }

  private static async saveStore(store: Record<string, string>): Promise<void> {
    const masterKey = await getMasterKey();
    const iv = randomBytes(16);

    const cipher = createCipheriv('aes-256-gcm', masterKey, iv);
    const plaintext = Buffer.from(JSON.stringify(store), 'utf-8');

    const encrypted = Buffer.concat([cipher.update(plaintext), cipher.final()]);
    const authTag = cipher.getAuthTag();

    writeFileSync(this.fallbackPath, Buffer.concat([iv, encrypted, authTag]), { mode: 0o600 });
  }
}
```

Edge Runtime can't bundle native Node addons like `better-sqlite3`'s compiled binary, so any import chain from `middleware.ts` that reaches it fails the build with a `Module not found` error (discovered during Task 11's build verification — Task 10's own review only ran `typecheck`/`vitest`, which don't catch Edge Runtime bundling violations; only an actual `next build` does). ```ts
// apps/web/middleware.ts
import { NextResponse } from 'next/server';
import NextAuth from 'next-auth';
import { authConfig } from '@/lib/auth.config';

const { auth } = NextAuth(authConfig);

const PROTECTED_ROUTES = ['/dashboard', '/search', '/outreach', '/contacts', '/settings', '/import'];
const PUBLIC_ROUTES = ['/login', '/card', '/api/auth', '/api/health'];

export default auth((req) => {
  const { pathname } = req.nextUrl;

  if (PUBLIC_ROUTES.some((route) => pathname.startsWith(route))) {
    return NextResponse.next();
  }

  if (PROTECTED_ROUTES.some((route) => pathname.startsWith(route))) {
    if (!req.auth?.user) {
      return NextResponse.redirect(new URL('/login', req.url));
    }
  }

  return NextResponse.next();
});

export const config = {
  matcher: ['/((?!_next/static|_next/image|favicon.ico).*)'],
};
```

`middleware.ts` builds its own lightweight `NextAuth(authConfig)` instance directly from `auth.config.ts` — it does NOT import `auth` from `./lib/auth`. This is the entire point of the split: `middleware.ts`'s import graph now never reaches `@netpro/db`/`better-sqlite3`, so it compiles cleanly for the Edge Runtime. Verify this with an actual `npm run build -w apps/web` (not just typecheck) — that's the only thing that catches an Edge Runtime bundling violation.

import { NextResponse } from 'next/server';
import { sql } from 'drizzle-orm';
import { conn } from '@/lib/db';

export const dynamic = 'force-dynamic';

export async function GET() {
  const start = Date.now();
  try {
    if (conn.dialect === 'sqlite') {
      conn.db.run(sql`SELECT 1`);
    } else {
      await conn.db.execute(sql`SELECT 1`);
    }
    return NextResponse.json({
      status: 'healthy',
      dialect: conn.dialect,
      latencyMs: Date.now() - start,
      timestamp: new Date().toISOString(),
    });
  } catch (error) {
    return NextResponse.json(
      { status: 'unhealthy', error: (error as Error).message },
      { status: 503 }
    );
  }
}
