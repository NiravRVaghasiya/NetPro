# v2.0 Phase 3 — Warm-intro pathfinder surface — progress & verification

Implements Phase 3 of the [v2.0 plan](2026-09-07-v2.0-implementation-plan.md),
building directly on [Phase 2's analytics engine](2026-09-07-v2.0-phase2-graph-analytics-progress.md)
and [Phase 1's edge provenance](2026-09-07-v2.0-phase1-edge-provenance-progress.md).

## What shipped

- **`packages/core/graph/pathfinder.ts` extension** (no new files beyond it +
  `position.ts`):
  - `planIntroPaths(conn, { target, from?, maxDepth?, relation?, status? }, { k })`
    — the ONE call both surfaces make. Resolves `id | exact email | full name`
    selectors (email/id exact wins; unique full-name substring, case/space
    normalized; ambiguous → `GraphError invalid_input`, none → `not_found` —
    the CLI/web just map the code), runs one `buildGraph` + one `contactMeta`
    batch read, returns the target/origin cards, `found`, `unreachable`, and
    `k` ranked paths.
  - `defaultPathOrigin(conn, { exceptContactId? })` — strongest tie
    (score-coalesced DESC, recency DESC, id ASC). **Skips the target itself**
    (a uniform-score fresh network used to make the freshest contact — often
    the target — its own origin; found by the live smoke, fixed with a
    regression test). No other live contact → clear `not_found`.
  - `rankIntroPaths(graph, target, paths, k)` + `scoreIntroPath` —
    `0.6 × min(hop relationship scores) + 0.4 × mean(strength × confidence)`
    (2dp). Unscored hop → 0; missing `weakestTie` on a 1-hop direct path =
    "you've never rated this tie", scored as 0, not 1. Ties break on the
    joined contactId chain — byte-deterministic, verified across DB handles.
  - `buildAsk` — the ask node is the strongest intermediate; when the ORIGIN
    is that person you ask them directly; when the target is adjacent to the
    ask, the suggestion names the relation of the **ask→target edge** (found
    live: it cited the wrong hop first). `introAskText(plan, pathIndex)` is
    the shared prefill string both surfaces reuse.
  - `buildIntroAskInput(plan)` — feeds the **existing** Phase 4
    `composeOutreachDraft` pipeline (tone `warm`; context = the ask text +
    target card; the contactId IS the ask person, so their notes/score/last
    touch enrich the prompt via the repo's usual merge). Draft-only; the
    provider is injected in tests.
- **`paths.ts`**: `IntroPathNode` gains `lastInteraction` (the 1-hop warm-intro
  candidates on `/dashboard` keep working — additive field).
- **CLI `netpro path <target>`** (`apps/cli/src/commands/path.ts`):
  `--from` (email/name/id), `--max-depth` (1–8, default 4), `--relation`,
  `--status`, `--alt 1–5` (k), `--draft`, `--json`, `--tone/--sender/
  --provider` like `netpro outreach`. Chain lines decorate every hop with
  `score + last` and each hop with `rel/conf/one-way` provenance; no-path
  says so and hints (`link people … or widen`); selection errors exit 1.
  A failing `--draft` prints the plan **and** exits non-zero
  (`executePathDetailed` returns `{output, json, draftError}` so the plan is
  never lost to a provider hiccup — the action checks `draftError`).
  Registered after `analyze` (shared theme).
- **Web `/graph`** (`app/(app)/graph/page.tsx`): server-rendered GET form
  (target/from pickers backed by a top-50 `searchContacts` datalist, depth
  select 1–6, relation + status selects), ranked chain cards with per-hop
  provenance + node score/recency, honest "(your strongest tie — set "From"
  to pick someone else)" disclosure, one-click **Draft intro request**
  → `/outreach?contactId=&context=&purpose=` deep link, and the Overview
  strip (clusters/centrality/components/avg-path + warm candidates with
  "Plan an intro" links). `GraphError` renders inline (`role="alert"`),
  never a throw; malformed hand-typed query params fall back to the defaults
  the selects would have produced.
- **Web `/graph/[contactId]`** (`getContactGraphPosition` in core): degree +
  rank (rank across `limit` only, with a note when truncated), betweenness
  (or why it's missing: over-budget note vs "not in the analyzed graph"),
  community, reachability at depth, your own direct tie (relation/conf/
  one-way/status or "no direct tie"), adjacency table **including pending**
  rows with inline confirm links (the page doubles as the confirmation entry
  point), and the warm-intro suggestions the contact appears in. Unknown id
  → `notFound()`.
- **Outreach composer prefill**: `?contactId=` (validated against live
  contacts, soft-deleted ignored — unknown params are silently dropped),
  `?context=`, `?purpose=`, `?tone=` flow into the existing composer;
  a prefilled contact re-runs the history/stats side-queries the manual
  picker runs. `lib/queries/outreach.ts` untouched.
- **API** (`apps/web/lib/graph-request.ts` shared parse+validate):
  `GET /api/graph/paths?target=&from=&depth=&relation=&status=&k=` and
  `GET /api/graph/overview?depth=&limit=` — owner-only via the proxy like
  every `/api` route, `force-dynamic`, and every bad-param case → explicit
  400 (`relation|depth|limit|minConfidence` from the shared analytics
  parser; `target` required ≤320 chars; `k` 1–5). **Web/API depth caps at 6**
  (the page/API mirror what the graph can carry); the engine+CLI keep 1–8.
  Unknown target → 404, ambiguous selector → 400 (mapped from `GraphError`).
- **Nav + proxy**: "Graph" link between Edges and Outreach; `/graph` added
  to `PROTECTED_ROUTES` (both the page redirect and API 401 covered by tests).
- **No migration** (Phase 1's `0003` covers every column read), **no new
  runtime dependencies**, Postgres-only path stays covered by the shared core
  (both dialects go through the same pure functions).

## Decisions & notes

- **Depth caps differ by surface on purpose**: web/API clamp to 1–6 (form
  select max 6; longer chains are CLI/script territory), engine+CLI keep the
  documented 1–8. `PATHFINDER_LIMITS.webMaxDepth` carries the constant.
- **Prefill = URL params, not a store**: `/outreach?contactId=&context=
  &purpose=` is shareable, server-rendered, and testable; the composer seeds
  its state from props (no effect-on-mount hacks). Unknown contactId params
  are ignored rather than 404-ing the outreach page (a stale link should not
  break the page).
- **`/graph` page fetches overview + plan itself** (server component, no
  client fetches, no SWR — consistent with every other page in the app);
  nested async children were refactored to sync props after
  `renderToStaticMarkup` surfaced a suspend-under-sync-input hazard.
- **Ask-node relations cite the ask→target edge** when adjacent (semantic:
  "the link that goes straight to them"), and the label is omitted when the
  edge has no relation info.
- The plan's deferred item ("auto-suggest which intermediary to lean on")
  stays deferred: ranking + first-ask + prefill is the surface; choosing is
  the human's.
