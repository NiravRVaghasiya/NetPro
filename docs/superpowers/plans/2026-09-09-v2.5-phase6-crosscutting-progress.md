## What shipped

Phase 6 is the glue phase: the two v2.5 features (profile views, content
tracker) are tied into the shared analytics payload, the two unbounded
tables get their retention job, and the plan's performance budgets are
measured, recorded, and enforced as hermetic tests.

- **Dashboard (`getNetworkOverview`):**
  - New `content` block (the all-time `ContentOverview`) beside the Phase 3
    `views` block, computed in the same `Promise.all` as everything else.
    `includeContent: false` omits it; `GET /api/analytics?content=0` opts
    out, exactly like `?graph=0` / `?views=0`.
  - `/dashboard` now renders the "Content" strip from `overview.content` —
    the separate `getContentOverview(conn)` call is gone, so the page and
    the API read one payload and cannot disagree.
  - **Two-step onboarding empty states** (the plan's
    "Add your first content" / "Share your card"): the Content strip
    renders "No content tracked yet. **Add your first content** → /content"
    while the library is empty (previously it rendered nothing), and the
    Profile views strip already points at "Publish your card → /settings/card"
    when there are no views. The no-contacts first-run page shows the
    content step too.
- **Retention & privacy:**
  - `purgeExpiredContentMetrics` (`packages/core/src/content/retention.ts`):
    deletes `content_metrics` rows older than the window (default **365
    days**) — with the keep-latest rule: a snapshot is deleted only when it
    is *strictly* older than the newest snapshot of its item, so the latest
    snapshot per piece always survives even when it predates the window,
    and ties for newest all survive. Portable correlated-subquery SQL,
    answered by Phase 4's `(content_id, fetched_at)` index.
  - `runRetentionPurge` (`packages/core/src/retention.ts`): composes it
    with Phase 1's `purgeExpiredProfileViews` (90 days) behind a 24 h guard.
    The guard's state is the audit log itself — the newest
    `activity_log` row with `action = 'retention.purge'` — so "daily"
    means *at most one run per 24 h, decided by the data, not the
    process*. Each run writes one audit row carrying the deleted counts
    (never one row per row); the write is best-effort, and a failed log
    just means the next tick re-runs the idempotent deletes.
  - Web scheduling (`apps/web/lib/retention.ts`, started from
    `instrumentation.ts` after the startup migrations, independent of
    `NETPRO_AUTO_MIGRATE` — DML, not DDL): one run at process start plus a
    24 h unref'd interval. Docker: boot + daily timer. Serverless: cold
    starts all re-check the audit log and no-op unless a day has passed;
    a same-second race deletes twice (idempotently) and logs twice.
    Failures are logged and swallowed — retention never breaks a page.
  - Operator knobs (lenient parsing: garbage/zero/negative fall back to
    the default — a typo must not widen the window to "delete
    everything"): `NETPRO_DISABLE_RETENTION=true`,
    `NETPRO_VIEW_RETENTION_DAYS` (90), `NETPRO_CONTENT_METRIC_RETENTION_DAYS`
    (365).
  - **Settings UI**: the tracking panel's "Stored (90 days, then purged)"
    now reads the effective windows from the same `retentionConfig` the
    job uses, and documents the content-snapshot horizon and the daily
    job. UI and database promise the same horizons.
  - **Pixel guarantees under test**: `GET /api/card/pixel.gif` — no
    `Set-Cookie` (Phase 2) and no raw IP in any stored column (Phase 2)
    stay, plus a new regression test that the raw IP never reaches the
    server logs.

## Notes / decisions vs the plan

- **The audit log is the scheduler state.** The plan says "in-memory, no
  queue infra". The cadence state deliberately lives in `activity_log`
  (one existing row) instead of a new table or a cron service: it survives
  restarts, works per-deployment without config, and doubles as the
  operator-visible audit of what was deleted when.
- **Keep-latest is a strict inequality.** "Latest per content" is defined
  as *not strictly older than any sibling*. Ties for the newest timestamp
  all survive — the alternative (guess one winner by id) would silently
  delete data that is equally valid.
- **`writeActivityLog` gained an optional `createdAt`.** The purge stamps
  its audit row with the operation's clock (`now`), so tests are
  deterministic and the row and the deletes agree on "when". Backward
  compatible (defaults to the real clock).
- **The content block is all-time, window-less.** The dashboard strip
  never had a window; the fold-in keeps the numbers identical. A window
  option can join `AnalyticsOptions` when a surface needs one.
- **`netpro analyze` is unaffected in text form** (the renderers print
  known sections); `analyze --json` gains the additive `content` field,
  consistent with the "one shared payload" rule.
- **Retention runs even with `NETPRO_AUTO_MIGRATE=false`** — it is DML, not
  DDL; on an unmigrated database the deletes fail, get logged, and never
  surface to request paths.
- No database migration and no new runtime dependencies.
