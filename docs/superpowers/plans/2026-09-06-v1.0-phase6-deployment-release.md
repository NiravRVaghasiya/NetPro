      server; capture the measurement before changing anything.
- [x] Shared advisory-locked migration runner (`packages/db/src/migrate.ts`)

      idle-client error handler, ephemeral-SQLite-on-Vercel guard.

      `NETPRO_TEST_DATABASE_URL`, including the mutation-verified race test.

- [x] Production security headers; `/api/*` no-store; `poweredByHeader: false`.

- [x] Diagnose and fix the production `UntrustedHost` authentication failure.
- [x] Docker: CLI in the image, one-shot migrate job, Postgres unpublished.
- [x] CI: Node 20/22 matrix, live Postgres job, Docker build + boot smoke test.
- [x] `docs/deployment.md`, environment examples, README.
- [x] Full verification against real PostgreSQL; record limits honestly below.

## Verification record

Baseline (before this phase, Node 22.22.3): lint, typecheck, **356 tests**, and
build pass. Build emits **6 warnings** (1 middleware deprecation + 5 Edge
runtime). `better-sqlite3` required a local source build — the sandbox cannot
reach `nodejs.org` for prebuilt headers, so `npm ci` was run with
`--ignore-scripts` and the addon compiled against the installed Node headers.
This is an environment limitation, not a repository defect.

### Findings (both pre-existing, both release-blocking)

1. **Concurrent migrations failed 5 of 6 workers** against real PostgreSQL 18
   on a fresh database — `CREATE TABLE "account"` and
   `CREATE SCHEMA IF NOT EXISTS "drizzle"`. This is the exact shape of a Vercel
   deploy. Fixed with a session advisory lock.
2. **Production authentication was completely broken** with NetPro's own
   documented configuration: `UntrustedHost`, every request 401, providers
   endpoint returning a configuration error. Auth.js v5 does not derive host
   trust from `NEXTAUTH_URL`. Masked in development by the `NODE_ENV` clause and
   on Vercel by the `VERCEL` clause — only a production build on a non-Vercel
   host reveals it.

### Results (2026-09-06, Node 22.22.3, PostgreSQL 18.4)

- `npm run lint` — passed.
- `npm run typecheck` — passed.
- `npm run test` — **402 tests in 55 files passed** (from 356; **+46**), plus
  7 live-Postgres tests skipped without a database. Core 206, CLI 75, web 93,
  db 27, UI 1.
- `npm run test -w @netpro/db` with `NETPRO_TEST_DATABASE_URL` — all **7**
  PostgreSQL integration tests passed.
- `npm run build` — passed with **zero warnings** (was 6).
- **Mutation-verified the race test**: disabling the advisory lock makes it fail
  with the original `CREATE TABLE "account"` / `CREATE SCHEMA` errors; restoring
  it passes. The test genuinely covers the bug.
- Real built CLI against real PostgreSQL: `migrate --status` on an empty
  database reported `0/2` pending; `migrate` applied `2/2`; re-running reported
  "already up to date". Ran correctly from the standalone layout too.
- CLI error paths: missing `DATABASE_URL`, unreachable host, and TLS mismatch
  each produced a targeted hint and exit code 1 — no stack traces.
- **Production standalone server against real PostgreSQL**, configured with
  only `NEXTAUTH_URL` (the documented setup that was broken):
  `/api/auth/providers` returns the GitHub provider; owner `GET /api/card` 200;
  `PUT` draft 200 while `/card` stayed 404 (draft privacy preserved); `POST`
  publish 200 and `/card` 200; vCard downloaded correctly; bad-origin write 403;
  `DELETE` 200 and `/card` back to 404. Non-owner and legacy JWTs both 401.
  **No `UntrustedHost` errors in the log.**
- Health endpoint: `healthy` 200 on a migrated database; **`degraded` 503 with
  "Database schema is not initialized" on an unmigrated one**; anonymous
  callers receive no migration counts or driver detail; owner `?verbose`
  returns `{"applied":2,"expected":2}`.
- Security headers verified live on the production server: CSP, HSTS,
  `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`,
  `Permissions-Policy`; `/api/*` `no-store`; no `X-Powered-By`.
- Signed-out `/api/card` 401, `/settings/card` 307, unpublished `/card` 404 —
  all Phase 5 boundaries intact on Postgres.
- Owner authorization used JWTs signed with the server's own ephemeral test
  secret and a synthetic identity: the normal Auth.js path, **not** a bypass.
- No dependency or lockfile changes. Scratch databases, tokens, and logs were
  kept outside the Git checkout.

### Verification limits / next phase

- **No real GitHub OAuth round trip.** It requires operator credentials and a
  public callback URL. Owner *authorization* is verified; the OAuth *handshake*
  is not.
- **No actual Vercel deployment.** `vercel.json`, the build script, and the
  serverless-shaped behaviour (pool sizing, concurrent migration, SQLite guard)
  are verified locally against real PostgreSQL, but no deploy to Vercel
  infrastructure was performed.
- **The Docker image was not built here** — no Docker daemon in the sandbox.
  The Dockerfile and Compose changes are exercised by the new CI job instead.
  The CLI-from-standalone-layout path that the image depends on *was* verified
  directly.
- PostgreSQL 18.4 was used locally; CI uses 16-alpine.
- Browser-based UI smoke tests were not repeated; Phase 5 covered the editor
  and this phase changed no UI. HTTP-level checks covered the routes.

v1.0 is now deployable and verified against a real database on both dialects.
Remaining roadmap work is v1.5 — CRM interaction tracking, follow-up reminders,
and batch campaigns — which unlocks the deferred graph analytics, relationship
scoring, SMTP delivery, and hybrid search.
