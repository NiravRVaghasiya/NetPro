# NetPro v1.0 Phase 5 implementation — Profile Card

See the [design and repository assessment](../specs/2026-09-06-v1.0-phase5-profile-card-design.md).

## Implementation checklist

- [x] Core public-profile contract: validation, limits, safe link helpers,
      standalone HTML, UTF-8-safe vCard, and adversarial tests.
- [x] SQLite/Postgres profile-card schemas and additive migrations; shared
      migrated SQLite test fixture; draft/publish/unpublish repository tests.
- [x] CLI `card` command, output/validation tests, documented sample profile.
- [x] Auth.js route; fail-closed single-owner GitHub authorization; old-session
      invalidation; segment-aware middleware and authorization tests.
- [x] Owner-only card API with origin/body/size checks and private responses.
- [x] Private editor + preview and public published-only page/download;
      publication, metadata, and render tests.
- [x] README, getting-started, environment examples, Docker owner configuration.
- [x] Full verification and live smoke tests; record honest limitations below.

## Verification record

Baseline: lint, typecheck, 234 tests, and build pass on Node 22.22.3. Existing
Next middleware/instrumentation warnings remain. No dependencies added.

Implementation verification (2026-09-06, Node 22.22.3):

- `npm run lint` — passed across the workspaces with lint tasks.
- `npm run typecheck` — passed.
- `npm run test` — **356 tests in 51 files passed**, up from 234 tests
  (**122 new tests**). Core: 206; CLI: 66; web: 80; db: 3; UI: 1.
- `npm run build` — CLI and Next.js production builds passed. The public page,
  vCard, editor, private API, and Auth.js catch-all appear in the route output.
- Both dialect migrations generated; the SQLite tests exercise a fresh
  database and an existing Phase 4 database, preserving contacts/auth users
  and proving repeat migration application is idempotent.
- Production **standalone** server started successfully with packaged
  migrations and copied static/public assets, bound to `0.0.0.0`. Health 200;
  signed-out private API 401; editor 307; unpublished page/download 404;
  published page/download 200. The Arena proxy host is accepted.
- `/api/auth/providers` returns the mounted GitHub provider. Requests signed
  with a test-only owner JWT succeed; non-owner and legacy JWTs are denied.
  Bad-origin writes are denied. This uses an ephemeral local secret and
  synthetic identity, **not** a real GitHub OAuth round trip or auth bypass.
- Chromium browser smoke against that production server: populate editor,
  save draft, confirm publication, publish, copy link, download profile JSON
  and vCard, edit/save privately without public leakage, unpublish, retain
  unsaved edits, recover from network failure, and display session-expiry
  guidance. All passed with no JavaScript page errors.
- Public card checked at 1440px desktop and 390px mobile; no horizontal
  overflow. Production responses have no-store/noindex/no-referrer headers,
  and anonymous card visitors receive no Auth.js cookies. Screenshots were
  inspected; the smoke test caught and fixed an ambiguous biography label.
- Real built CLI generated HTML and vCard from `docs/examples/profile.json`.
  The standalone HTML rendered in Chromium; its embedded vCard download
  worked, with **zero external HTTP requests**.
- No changes to dependency manifests or lockfile. Browser tooling, credentials,
  screenshots, generated HTML/vCard, logs, and the fictional preview database
  were kept outside the Git checkout in sandbox scratch storage.

### Verification limits / next phase

Postgres schema/query types compile and its additive migration is committed,
but **no live PostgreSQL integration run** was performed. No real GitHub OAuth
provider round trip, Docker image build, or Vercel deployment was performed.
The existing Next.js middleware deprecation and instrumentation Edge-runtime
warnings remain; they predate this work. These are recorded release-readiness
items, not grounds to call this a production v1.0 release.

Phase 6 should deliver one-click Vercel + managed Postgres, production migration
execution and concurrency verification, Docker/environment hardening, and the
remaining end-to-end release checks. CRM/campaigns stay on the later roadmap.
