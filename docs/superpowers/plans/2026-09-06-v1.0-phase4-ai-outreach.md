# NetPro v1.0 Phase 4 Implementation Plan — AI-Powered Outreach (Drafting)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the AI outreach drafting engine in `packages/core/src/ai` (provider abstraction for OpenAI-compatible + Anthropic over raw `fetch`, prompt builder, draft parser/composer), wire it into `netpro outreach` (CLI) and `/outreach` + `POST /api/outreach` (web), and replace the `/settings` stub with a read-only integration-status panel. BYO-key: CLI uses the existing encrypted `Keychain`; web reads server env vars only.

**Architecture:** One new/real module `packages/core/src/ai/` (`types`, `providers/openai`, `providers/anthropic`, `prompt`, `parser`, `compose`, `credentials`, `index`). The engine is database-free and network-injectable — providers take an optional `fetchImpl`, `composeOutreachMessage` takes a provider — so every test runs offline with fakes. CLI and web own credential resolution and contact lookup; core owns prompt/parse/compose. **No new dependencies.**

**Tech Stack:** TypeScript (strict), global `fetch` (Node 20+), Vitest with the in-memory SQLite harness for contact-resolution tests, React client component for the composer (the repo's first client-side fetch UI).

## Global Constraints

- All Phase 1/3 plan constraints carry over: pins on `typescript@^5`, `commander@^14`, `better-sqlite3@^12` stay untouched; **no new npm dependencies** (no OpenAI/Anthropic SDKs, no zod — hand-rolled validation consistent with existing routes); `crypto.randomUUID()` is not needed (no persisted entities); `SqliteConn | PgConn` union narrowing by `conn.dialect` where a query is unavoidable.
- No network calls in tests: inject `fetchImpl` into providers and inject a provider into `composeOutreachMessage`.
- Secrets: never log, never include in errors, never render. Web reads keys only from `process.env`; CLI uses `Keychain`. Error messages name the provider and status, never the key.
- Input limits (Security doc §5.1 philosophy): tone whitelist; context ≤2000 chars; purpose ≤500; names ≤200; ad-hoc email must be a valid email shape.
- Every task ends with `git add` + `git commit` for exactly the files that task created or modified, plus a green `npm run lint && npm run typecheck && npm run test` for the affected workspace(s).

- Modify: `packages/core/src/ai/index.ts`

**Interfaces:**
- `ChatMessage = { role: 'system' | 'user' | 'assistant'; content: string }`;
  `AiCompletionOptions = { model?: string; temperature?: number; maxTokens?: number; signal?: AbortSignal }`;
  `AiProvider = { id: 'openai' | 'anthropic'; label: string; defaultModel: string; complete(messages, opts?): Promise<string> }`.
- `ProviderConfig = { apiKey: string; baseUrl?: string; model?: string }`;
  `createOpenAiProvider(config, fetchImpl?): AiProvider` —
  `POST {baseUrl ?? 'https://api.openai.com/v1'}/chat/completions`,
  auth header `Authorization: Bearer <key>`, body
  `{ model: config.model ?? defaultModel, messages, temperature: opts?.temperature ?? 0.7, max_tokens: opts?.maxTokens ?? 600 }`;
  returns `choices[0].message.content`; non-ok → `Error('OpenAI request failed: <status> <error message if present>')`.
- `createAnthropicProvider(config, fetchImpl?): AiProvider` —
  `POST https://api.anthropic.com/v1/messages`, headers
  `x-api-key`, `anthropic-version: 2023-06-01`; body
  `{ model, max_tokens, system: <system message>, messages: <user/assistant only> }`;
  returns `content[0].text`; same error convention. System message is split out of the messages array per the Anthropic API.
- `createAiProvider(id, config, fetchImpl?)` factory +
  `AiProviderError` class with `code: 'not_configured' | 'upstream_error' | 'invalid_response'`.
- `resolveAiProvider(creds: { provider?: string; openaiKey?: string | null; anthropicKey?: string | null; openaiBaseUrl?: string | null; model?: string }, fetchImpl?): AiProvider` —
  chooses provider (explicit `provider` else whichever key exists, preferring openai), throws `AiProviderError('not_configured')` with a user-actionable message when no key.
- Default models: openai `gpt-4o-mini`; anthropic `claude-haiku-4-5-20251001` (cheap, fast, current).

- [x] **Step 1:** Types + both providers with fake-`fetch` tests (URL, headers, body shape, response extraction, error statuses, baseUrl override, system-message split for Anthropic)
- [x] **Step 2:** `resolveAiProvider` selection rules + not-configured error tests; `ai/index.ts` exports

### Task 5: Web — `POST /api/outreach`

**Interface:** `POST` JSON body `{ contactId?, recipient?: {name,email,company,role}, context?, purpose?, tone?, sender?, provider?, model? }`.

- Contact lookup by id reuses a portable select (narrow on `conn.dialect`).
- Tests follow the analytics route-test pattern (`vi.mock('@/lib/db')`, seeded in-memory SQLite) plus `vi.mock` of the core compose seam or env; assert statuses and JSON shapes.
