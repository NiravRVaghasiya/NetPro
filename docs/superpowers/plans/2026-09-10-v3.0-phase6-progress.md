## Deliberate plan adjustments

1. **Relative source URLs** resolve against the index URL (https base or
   index-file directory). The plan's example shows absolute URLs; relative
   resolution is what makes a mirrored index self-host without edits and
   what lets CI and offline operators use `file://` indexes.
2. **Archive-manifest-must-match-listing**: beyond the plan's sha256 check,
   name/version/permissions inside the archive must equal the index entry —
   a listing that advertises one thing and ships another is refused and
   audited.
3. **No migration.** The plan's `plugins` table from Phase 5 proved
   sufficient; no placeholder migration is shipped.
4. **Repo-root plugin fallback** in `getPluginDirs` (dev UX: processes
   started in `apps/*` see the checkout's `./plugins`); the install dir is
   always one of the runtime's load roots, so installs are loadable.
5. **Update staging**: updates materialize to a temp dir and only touch the
   live tree after verification, so a failed update never leaves a half tree.
6. **Downgrade refusal is audited** (`plugin.update_refused`) and
   force-overridable, per the plan's monotonicity rule.
7. Git sources require https/file (no ssh — non-interactive only) and verify
   `HEAD == pinned commit` after checkout; symlinks/non-files inside git
   trees are refused like tar entries.
