**Deferred, on the user's explicit choice** (fix-auth-gate-only, not the full Important list) — worth revisiting before or during the first feature spec that builds on this scaffold:

*Important:*
- `middleware.ts` is a deprecated Next.js convention (16.x warns to migrate to `proxy.ts` via `npx @next/codemod@canary middleware-to-proxy .`) — still works, not urgent.
- Both Drizzle schema files (`schema.sqlite.ts`, `schema.pg.ts`) use a deprecated third-parameter form on `primaryKey()` for `accounts`/`verificationTokens` — a scheduled break in the most load-bearing shared file, mechanical fix (array instead of object return).
- `packages/config` has no `lint`/`typecheck`/`test`/`build` scripts — Turborepo skips it entirely, so the file every other workspace's ESLint config imports is itself never linted.
- `@netpro/config` is an undeclared dependency in `packages/core` and `packages/ui` (works only via workspace hoisting); where it IS declared, it's in `dependencies` rather than `devDependencies` despite being lint/build-only tooling.
- No path from a clean clone to a working database: no `db:push`/`db:migrate` script anywhere, `migrations/` dirs are empty, and neither the Dockerfile nor docker-compose applies the schema — `/api/health` only runs `SELECT 1`, so the stack reports healthy on an empty database and the first real sign-in attempt would fail.
- `docker-compose.yml` publishes Postgres on `5432` to all host interfaces alongside `.env.example`'s `POSTGRES_PASSWORD=change-me` — the `web` service doesn't need the published port; drop the mapping or bind to `127.0.0.1`.
- CLI keychain hardening gaps (mostly already known from Task 8's own review): no recovery path if `hostname()` changes or the file corrupts (raw crypto error surfaces uncaught), non-atomic `writeFileSync`, `0o600` only applied at creation not enforced on existing files, `~/.netpro` directory not `0o700`.
- Keychain tests rely entirely on `vi.stubEnv('HOME'/'USERPROFILE')` working, with nothing asserting it did — a silent failure there would let tests clobber a real developer's `~/.netpro/credentials.enc`.
- `apps/web/lib/db.ts`'s `createDb()` runs as a module-scope side effect (opens a real DB connection at import time) — already produced an untracked `netpro.db` build artifact; benign today, will bite once feature code actually queries during prerendering.

## Cross-cutting lessons (apply to remaining tasks)

- Unpinned `npm install <pkg>` on a fast-moving package can resolve to a version that breaks compatibility with something else in the tree (TypeScript 7.x vs `typescript-eslint`; `commander@15` vs the Node `>=20` floor) — or, inversely, can dedupe against a stale transitive version already in the lockfile instead of fetching current (`commander` initially landed on `4.1.1` this way). Every implementer dispatch now carries an explicit instruction to verify resolved versions live, not just trust that `npm install` exiting 0 means correctness.
- Never accept a subagent's self-report at face value for anything security- or build-critical — every fix in this log was confirmed via independent re-execution (running ESLint against a real file, tamper-testing the crypto, re-running `tsc`/`vitest`/`next build` directly) before being marked approved.
- Two genuine plan-authoring bugs were found only through implementation (duplicate shebang; missing `packageManager` field) — both fixed retroactively in the plan document itself, not just patched in code, so a future rebuild from the plan doesn't repeat them.
