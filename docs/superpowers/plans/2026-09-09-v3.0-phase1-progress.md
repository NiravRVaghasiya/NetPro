## Goal
Introduce workspaces, members, roles, invites; put every data row in exactly one workspace; allow more than one GitHub account to sign in via invite while preserving single-owner compatibility.

## Data model (migration 0008)

- Added tables (both dialects):
  - `workspaces`: id, name, slug (unique), created_at. Bootstrap id = `default`, slug = `default`.
  - `workspace_members`: id, workspace_id FK cascade, user_id FK to Auth.js user, role (owner|admin|member|viewer default member), created_at, UNIQUE (workspace_id, user_id), indexes on workspace and user.
  - `workspace_invites`: id, workspace_id FK cascade, token (unique, HMAC-signed), role, expires_at, created_by, accepted_at, revoked_at, created_at, indexes on workspace and expires.
- Added `workspace_id` column (text, nullable in SQL, backfilled to `default`, thereafter always written via default('default') in Drizzle schema and explicit writes in core) to 16 data tables:
  contacts, interactions, follow_ups, campaigns, campaign_recipients, edges, events, event_attendees, content_items, content_metrics, content_mentions, enrichments, search_index, profile_views, activity_log, profile_cards.
- Composite indexes:
  idx_contacts_workspace, idx_contacts_workspace_updated,
  idx_interactions_workspace, idx_interactions_workspace_contact,
  idx_followups_workspace, idx_followups_workspace_status_due,
  idx_campaigns_workspace, idx_campaign_recipients_workspace,
  idx_edges_workspace, idx_events_workspace, idx_event_attendees_workspace,
  idx_content_items_workspace, idx_content_metrics_workspace, idx_content_mentions_workspace,
  idx_enrichments_workspace, idx_search_index_workspace,
  idx_profile_views_workspace, idx_profile_views_workspace_time,
  idx_activity_log_workspace, idx_activity_log_workspace_time,
  idx_profile_cards_workspace, plus members/invites indexes.
- Migration backfills all pre-existing rows to `default` and creates bootstrap workspace idempotently.
- FTS/search_index: added workspace_id column; existing reindex fallback documented.

## Auth changes

- `apps/web/lib/auth.config.ts` unchanged (GitHub provider)
- `apps/web/lib/auth.ts`:
  - `signIn` now: if NETPRO_OWNER_GITHUB_ID missing, allow any (bootstrap path); if no members exist, auto-provision owner as first member with owner role via `ensureBootstrapWithOwner`; if user has membership in any workspace, allow; if no membership, check for pending valid invite? For Phase 1, deny (invite acceptance happens via /invite page after sign-in).
  - `jwt` callback: resolve membership via `getMembershipForUser`, store workspaceId/role in token; if revoked, token null (forces sign-out); but allow token for /invite flow even without membership (limited session).
  - `session` callback: expose workspaceId/role.
  - Added helpers `getMembershipForUser` in `apps/web/lib/workspaces.ts` using Drizzle conn.
- `apps/web/proxy.ts`: added `/invite` to PROTECTED_ROUTES (any authenticated GitHub user can access invite acceptance), other routes still enforce membership via `requireScope()` helper.
- `apps/web/lib/authz.ts` new: `requireAuth()` and `requireMembership(minRole)` helpers that resolve membership and enforce role via `canAtLeast`.
- `apps/web/lib/crm-request.ts`: extended to handle `WorkspaceError` (401/403) mapping.

## Invites

- `packages/core/src/workspaces/tokens.ts`: HMAC-signed expiring invite tokens, `verifyInviteToken`, `isInviteExpired`. Uses NEXTAUTH_SECRET, 7-day default, single-use, revocable.
- `packages/core/src/workspaces/repository.ts`: CRUD for workspaces/members/invites, `ensureBootstrapWorkspace`, slug validation, `getWorkspaceMembers`, `addMember`, `removeMember`, `updateMemberRole`, `createInvite`, `listInvites`, `getInviteByToken`, `revokeInvite`, etc.
- `packages/core/src/workspaces/service.ts`: `ensureBootstrapWithOwner`, `resolveMembership`, `acceptInviteByToken`, `assertCanRemoveMember`, `assertCanChangeRole` with break-glass protection (cannot remove last owner, cannot demote break-glass owner).
- `packages/core/src/workspaces/types.ts`: `WorkspaceRole`, `roleRank`, `canAtLeast`, `WorkspaceError`.
- `packages/core/src/workspaces/index.ts` barrel.

## Web surfaces

- `/invite/[token]` page:
  - `apps/web/app/(app)/invite/[token]/page.tsx` server component verifies token via `verifyInviteToken`, loads invite via `getInviteByToken`, checks revocation/expiry/acceptance, checks if already member, renders client.
  - `client.tsx` allows acceptance via POST /api/invites/accept, then redirects to /dashboard.
- Team admin:
  - `apps/web/app/(app)/settings/team/page.tsx` requires admin membership, lists members with user details (join via users table), lists invites, renders `TeamClient`.
  - `client.tsx` provides create invite (POST /api/workspaces/invites), revoke, change role (PATCH /api/workspaces/members), remove member (DELETE).
  - Added Team link to nav and settings overview.
- API routes:
  - `GET /api/workspaces/members` (viewer+), `POST` (admin, add member), `PATCH` (admin, change role with break-glass check), `DELETE` (admin, remove member)
  - `GET /api/workspaces/invites` (admin), `POST` (admin, creates HMAC token, audit logs)
  - `DELETE /api/workspaces/invites/[id]` (admin, revoke)
  - `POST /api/invites/accept` (any authenticated, accepts token)
  - `GET /api/invites/[token]` (public token validation, no auth, returns valid/invalid)
- Audit logging for invite created/revoked/accepted into activity_log with workspace_id.

## Risks mitigated

- Additive migration, idempotent, backfill count-asserted in tests.
- Break-glass owner protection prevents removal of last owner.
- HMAC tokens prevent tampering.
- Default workspace_id ensures single-owner installs never break.
