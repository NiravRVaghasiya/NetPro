# NetPro v1.0 Phase 3 — Network Analytics — Design

> Status: Implemented
> Builds on: Phase 1 (Import, Enrichment & Export), Phase 2 (People Search)
> Source blueprints: `NetPro — Blueprint.md` (MVP "Network Analytics" row, CLI
> reference `netpro analyze`, `/dashboard` page detail), `NetPro — DB & Pipeline
> Deep Dive.md` (§1.5 dormant connections, §2.6 Stage 5 Analytics & Scoring Engine)

## Purpose

Phases 1–2 put contacts in the database and made them findable. Phase 3 makes
the network *legible*: a composite network health score, activity/dormancy
breakdown, growth over time, diversity, and clusters — computed once in
`packages/core` and surfaced through `netpro analyze` (CLI) and `/dashboard` +
`GET /api/analytics` (web). This replaces the last three "not yet implemented /
coming soon" analytics stubs (core `analytics` module, CLI `analyze`, web
`/dashboard`).

## Scope

**In scope:**
- **Network metrics** — total contacts; active (interaction within 30 days);
  dormant (no known interaction within 90 days, configurable); average
  relationship score.
- **Network score** — 0–100 composite. The blueprint's five factors collapse to
  four while the `edges` table is empty (see Key decisions): activity 35%,
  diversity 30%, size 20%, growth 15%.
- **Growth** — new contacts in the last 30 days vs the prior 30 (rate) plus a
  12-month month-by-month series with running cumulative total.
- **Diversity** — Shannon entropy over industries (fallback: companies when
  industry is sparse), reported as an "effective number of categories"
  (exp(H)), which is human-readable ("your network spans ≈7 distinct
  industries").
- **Clusters** — attribute-based grouping by normalized company (top-N by size,
  each with member count and top roles). This is the honest v1: the blueprint's
  Louvain community detection needs the `edges` table, which nothing populates
  yet.
- **Dormant ties** — the reconnect list: contacts whose last known interaction
  (or, if never interacted, their connection date) is older than the window,
  most-relevant first (relationship score desc, then longest-ago).
- **Import change (deliberate, cross-phase):** LinkedIn's "Connected On" date
  is parsed today and discarded. Import now persists it — `createdAt` and
  `lastInteraction` are set to the connection date when parseable, falling back
  to import time. Without this, growth is a single spike at import time and
  dormancy is undefined for every imported contact. The merge path backfills
  `lastInteraction` when the existing row has none.
- CLI `netpro analyze` (replaces the stub): full report by default, with
  `--dormant`, `--clusters`, `--network-score` section views, `--days <n>`
  dormancy window, `--limit`, `--json`.
- Web `GET /api/analytics` (JSON overview) and the real `/dashboard` page:
  metric cards, SVG growth chart (server-rendered, no chart library), top
  companies/industries, clusters, and the dormant-ties table with an empty
  state pointing at `/import`.

**Explicitly deferred** (documented, not forgotten):
- **Graph-native analytics** — Louvain cluster detection, centrality, reach
  (average shortest path), and weak-tie/bridge scoring all operate on the
  `edges` table, which has no producer yet (LinkedIn's export has no
  contact-to-contact relationships). They arrive in the phase that *creates*
  edges (GitHub import / inferred shared-employer edges), building on the same
  `analytics` module entry points. Until then the network score's structure
  component is redistributed to the other factors.
- **Per-contact relationship scoring** — the blueprint's
  `computeRelationshipScore` needs interaction history (recency, frequency,
  direction balance, channel mix). The `interactions` table has no producer
  until the CRM phase; `relationshipScore` stays 0 for imported contacts.
- **Score decay job** (`decayRelationshipScores`, daily cron via Inngest/
  BullMQ) — nothing meaningful to decay until interaction logging exists.
- **Blueprint CLI flags `--path-to`** — warm-intro pathfinding is v2.0
  ("The Strategist") and requires edges.
- **Interactive network graph visualization** on `/dashboard` — needs the
  same edges data; the dashboard ships stat surfaces first.

## Key decisions

| Area | Decision | Rationale |
|---|---|---|
| Compute strategy | One lightweight projection scan (`SELECT` of 7 columns over non-deleted contacts) + pure-JS aggregation | Every metric (counts, entropy, growth buckets, clusters) is derivable from the same rows; one query keeps SQLite/Postgres behavior identical **with zero dialect branching** — the whole module is portable by construction. Simplifies tests to seeding rows + asserting numbers. |
| Network score weights | activity 0.35, diversity 0.30, size 0.20, growth 0.15 (renormalized from the blueprint's five factors minus structure 0.20) | The blueprint's structure factor counts cluster bridges — undefined with no edges. Rather than a permanently-crippled /80 score, weights are renormalized over measurable factors and the blueprint weights are restored when edges land. |
| Dormancy definition | `COALESCE(lastInteraction, created_at) < now − days` | A contact never interacted with is at least as stale as its acquisition date. Treating NULL as "not dormant" would hide everyone after a fresh import; treating NULL as dormant-by-createdAt surfaces the truth: these ties need attention. |
| Diversity metric | Shannon entropy over industry (fallback company when <2 distinct industries), reported as effective category count `exp(H)` | Blueprint specifies Shannon entropy of industries; the exponential gives an interpretable number instead of nats. Fallback keeps the number meaningful for imports where LinkedIn provides no industry (it doesn't — industry fills in via enrichment). |
| Clusters | Group by `lower(trim(company))`, top-N by size, with top roles per cluster | Honest v1 clustering over data that exists. Edge-based community detection is deferred with the rest of graph analytics. |
| Connection date | Import persists parsed `connectedOn` into `createdAt` **and** `lastInteraction` (ISO); invalid/missing → now | `connectedOn` is when the relationship started = the only truthful growth timeline, and "connected" is a real interaction. `createdAt` keeps meaning "when this relationship entered your network" rather than "when the CSV ran". Merge updates backfill `lastInteraction` only when empty, so re-imports never erase newer interaction data. |
| Determinism | All core functions accept `now?: Date` (default `new Date()`) | Growth windows, dormancy cutoffs, and month buckets are relative to "now"; injecting it makes tests deterministic without freezing timers. |
| Chart | Server-rendered inline SVG bars on `/dashboard` | Zero client JS, zero chart dependencies — consistent with the repo's minimal-dependency constraint (Phase 1's only additions were `papaparse`). |
| Auth | `GET /api/analytics` added to middleware `API_ROUTES` (401 JSON); `/dashboard` already gated by `(app)` layout + middleware `PROTECTED_ROUTES` | Same pattern as Phases 1–2. |
| Shared entry point | `getNetworkOverview(conn, opts)` returns the full overview; CLI and web are thin formatters | Matches the architecture rule that business logic lives in `packages/core` only. |

## CLI

```
netpro analyze
  [--days <n>]            # dormancy window in days (default 90)
  [--dormant]             # show only the dormant-ties section
  [--clusters]            # show only the clusters section
  [--network-score]       # print just the score line
  [--limit <n>]           # max rows per list (default 10)
  [--json]                # full overview as JSON
```

- Default (no section flag): network score card, metrics, top companies &
  industries, growth summary + sparkline, clusters, dormant preview.
- Invalid numeric flags fail with a clear message and exit code 1 (same
  `parseNumber` pattern as `netpro search`).
- `--json` always emits the complete overview regardless of section flags, so
  scripts can slice what they need.

## Web

- `GET /api/analytics?days=&activeDays=&months=&limit=` →
  `NetworkOverview` JSON; auth-gated (401 JSON when signed out).
- `/dashboard` — server component, URL-param-free (report knobs are fixed at
  sane defaults): metric cards (total / active 30d / dormant 90d / network
  score / growth last 30d), 12-month SVG growth bar chart with cumulative
  total, top-5 companies and industries with count bars, top clusters, top-10
  dormant ties (name, company, days since last touch, link to
  `/contacts/[id]`), and an empty state that routes to `/import`.

## Testing

- Core (`packages/core/src/analytics/*.test.ts`): deterministic seeds with an
  injected `now` — metrics counts (active/dormant windows, soft-delete
  exclusion), score components and bounds, growth buckets + rate + prior-window
  comparison, entropy (identical → 1 effective category, spread → more),
  clusters (normalization "Stripe, Inc." ≡ "stripe", top roles, ordering),
  dormancy list ordering and NULL-lastInteraction fallback, overview
  aggregation, and the new import persistence of `connectedOn`
  (`packages/core/src/import/*`).
- CLI (`apps/cli/src/commands/analyze.test.ts`): flag→options mapping,
  validation errors, section rendering (report, dormant, clusters, score),
  `--json`.
- Web (`apps/web/app/api/analytics/route.test.ts`): overview JSON shape,
  param parsing, error → 500.
- End-to-end: real CLI `import` → `analyze` against a freshly migrated SQLite
  DB; live `next dev` confirms `/api/analytics` 401 and `/dashboard`
  307→/login when unauthenticated.

## Success criteria

- `netpro analyze` prints a correct report from a real imported database;
  every section flag and `--json` work; invalid flags error clearly.
- `/dashboard` renders the same numbers from `GET /api/analytics`; both are
  auth-gated.
- Imported CSVs now carry their real connection timeline: growth reflects when
  relationships formed, not when the CSV was imported.
- Behavior is identical on SQLite and Postgres (single portable query path).
- `npm run lint && npm run typecheck && npm run test && npm run build` all pass
  repo-wide.
