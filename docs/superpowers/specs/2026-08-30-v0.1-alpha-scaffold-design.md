# NetPro v0.1-alpha Scaffold — Design

> Status: Approved
> Source blueprints: `NetPro — Blueprint.md`, `NetPro — Security & Auth Architecture.md`, `NetPro — DevOps & Deployment.md`, `NetPro — DB & Pipeline Deep Dive.md`

## Purpose

The four source documents describe the full NetPro product through v3.0: 15 features, a CLI + web monorepo, dual-database storage, a plugin marketplace, campaign automation, GDPR tooling, and multi-target deployment. That is too large to build in one pass.

This spec covers **only the v0.1-alpha milestone** from the blueprint's roadmap: a monorepo scaffold that installs, builds, lints, typechecks, and tests cleanly, with the real directory/module structure in place and every route/command represented by a stub. No feature logic (search, enrichment, AI outreach, CRM, campaigns) is implemented here — each becomes its own future spec built on top of this foundation.

## Decisions

| Area | Decision | Rationale |
|---|---|---|
| Scope | Scaffold only — no working feature slice | Blueprint describes an entire product; decompose into buildable increments starting with the skeleton |
| Surfaces | Both `apps/web` (Next.js) and `apps/cli` (commander + ink) | User confirmed both surfaces should exist from the start |
| Package manager | npm workspaces (not pnpm) | User preference; avoids installing an additional tool. Turborepo works with any package manager, so it stays |
| Database | Drizzle ORM, both SQLite and Postgres dialects wired now | User confirmed both dialects now, matching the blueprint's dual-mode design |
| DB encryption | Deferred (no SQLCipher yet) | SQLCipher requires a native build toolchain (node-gyp / VS Build Tools); shouldn't gate a first successful `npm install`. Plain `better-sqlite3` for now |
| Auth | Auth.js v5 wired with GitHub OAuth provider + Drizzle adapter + minimal middleware | Enough to compile and work once real OAuth credentials are supplied |
| Auth hardening | Deferred (rate limiting, CSRF, audit log, KeyVault encryption) | Real feature work, becomes its own future "Security Hardening" spec |
| CLI secrets | `Keychain` class, encrypted-file fallback path only (no `keytar`) | `keytar` is unmaintained/archived; avoid install-time risk in a scaffold whose job is to install cleanly. OS-keychain integration is a follow-up |
| Testing | Vitest wired at root, one trivial passing test per package | Proves wiring works without inventing tests for code that doesn't exist yet |
| E2E testing | Deferred (no Playwright yet) | No real UI flows exist yet to test meaningfully |
| CI | GitHub Actions: lint → typecheck → test → build | Matches DevOps doc's Stage 1–3; deploy/publish stages deferred until there's something to deploy |
| Docker | Dockerfile + docker-compose with web + Postgres only | Redis/worker/Caddy support features (rate limiting, job queue) that don't exist yet |
| Web pages | Every route from the blueprint exists as a real file with a "Coming soon" placeholder | Proves routing/layout/auth-gating without building the feature |
| Git | `git init` + initial commit as part of scaffolding | Folder isn't a repo yet; needed for CI and sane version control from the start |

## Database Schema

`packages/db/src/schema.ts` implements the full entity set from the DB & Pipeline doc: `contacts`, `interactions`, `edges`, `enrichments`, `campaigns`, `campaignRecipients`, `searchIndex`, `profileViews`, `followUps`, `activityLog`. Dialect is selected via `DB_DIALECT` env var (`sqlite` default, `postgresql` optional), matching the blueprint's `drizzle.config.ts` pattern. No RLS policies or FTS5 virtual tables in this pass — those are query-layer/feature work, not scaffold.

## Auth

`apps/web/lib/auth.ts` configures Auth.js v5 with:
- GitHub OAuth provider (Google/Resend deferred — same pattern, add later)
- Drizzle adapter pointed at `packages/db`
- JWT session strategy, 30-day max age
- `middleware.ts` with a protected-route list matching the blueprint's `PROTECTED_ROUTES`/`PUBLIC_ROUTES` split, redirecting unauthenticated users to `/login`

No rate limiting, CSRF tokens, audit logging, or API-key encryption vault in this pass.

## CLI

`apps/cli` uses commander for command parsing and ink for any interactive output. Each command (`init`, `import`, `search`, `outreach`, `analyze`, `track`, `export`) is registered and prints "not yet implemented" — proving the command tree, arg parsing, and build pipeline (tsup → single ESM bundle with shebang) work end to end.

`Keychain` (`apps/cli/src/config/keychain.ts`) implements only the encrypted-file fallback (AES-256-GCM, machine-ID-derived key) from the Security doc — no `keytar`/OS-keychain call yet.

## Testing & CI

- Vitest configured at the root (`vitest.config.ts`), one smoke test per package/app confirming imports resolve and a trivial function runs.
- `.github/workflows/ci.yml`: install → lint → typecheck → test → build, on push/PR to `main`. No deploy, npm publish, or Docker push jobs yet (nothing to deploy).

## Docker

`Dockerfile` (multi-stage, matching the DevOps doc's structure) builds the web app. `docker-compose.yml` runs `web` + Postgres only — Redis, the worker process, and Caddy are deferred until rate limiting/job queue/HTTPS-proxying features exist.

## Out of scope for this pass (explicitly deferred)

- Any real feature logic: import parsing, enrichment providers, search engine, AI outreach, CRM scoring, campaigns, graph analytics, profile-card pages
- SQLCipher encryption at rest
- Auth hardening: rate limiting, CSRF, audit logging, KeyVault
- OS-keychain (`keytar`) integration
- Playwright / E2E tests
- npm/Homebrew publishing, Docker image publishing, Vercel deploy config
- Plugin architecture (v3.0)
- Monetization/billing

Each of these becomes its own spec + implementation plan once the scaffold is in place.

## Success Criteria

- `npm install` succeeds from a clean clone
- `npm run lint`, `npm run typecheck`, `npm run test`, `npm run build` all succeed via Turborepo across every app/package
- `apps/cli`: `node apps/cli/dist/index.js --help` lists all seven commands
- `apps/web`: `npm run dev` serves the landing page and every route listed above without a 500 error (auth-gated routes redirect to `/login` as expected)
- `docker compose build` succeeds
- Repo is a git repository with an initial commit
