# NetPro v3.0.0 — “The Platform”

**The first tagged release of NetPro** — a local-first, open-source alternative
to LinkedIn Premium. Import your connections, search them properly, understand
the graph, keep the relationships alive — from a CLI, a local HTTP API and a web
UI that owns none of your data.

Everything runs on your machine: `netpro init` creates `~/.netpro` (config,
SQLite database, logs, keys) and `netpro serve` runs the whole application on
`http://127.0.0.1:3777`. There is no cloud account, no hosted platform and no
OAuth anywhere in the stack.

> **About the version number.** NetPro was built in public through a phased
> roadmap — v1.0 (import, search, analytics, AI drafts), v1.5 (CRM, follow-ups,
> campaigns), v2.0 “The Strategist”, v2.5 “The Observer”, v3.0 “The Platform”.
> This is the first time the code is cut as a **tagged, installable release**, so
> it lands as v3.0.0 rather than re-numbering the work that led here. No earlier
> version was ever published.

## Install

**Prerequisites:** Node.js ≥ 20. Nothing else — no Docker, no database server, no
account.

### CLI, from the release bundle

```bash
npm install -g https://github.com/NiravRVaghasiya/NetPro/releases/download/v3.0.0/netpro-3.0.0.tgz

netpro init       # creates ~/.netpro: config.toml, SQLite db, logs, keys
netpro serve      # http://127.0.0.1:3777 (foreground; Ctrl+C stops it)
netpro status     # install · database · identity · server health · providers
```

`netpro init` on a fresh machine:

```text
NetPro initialized

Created /home/you/.netpro
Database: SQLite — /home/you/.netpro/netpro.db (15/15 migrations applied)
Server:   127.0.0.1:3777
Config:   /home/you/.netpro/config.toml (created)
Identity: ins_f73d12621d35deb56159f85a (you) — created
Token:    np_N4h…b_kg at /home/you/.netpro/keys/access-token (created)
```

Then, from another terminal, against the same local database:

```bash
netpro import ~/Downloads/Connections.csv   # your LinkedIn export
netpro search "AI founders"                 # hybrid-capable search
netpro analyze                              # score, growth, clusters, dormant ties
netpro scan                                 # reindex + enrich + graph in one sweep
```

> **About the npm registry name.** The unscoped name `netpro` on npm is held by
> an unrelated package (a Node internet-protocol utility), so this release is
> distributed as the installable tarball above — `npm install -g <tarball-url>`
> installs the real `netpro` CLI with its bundled server, migrations and native
> database drivers. Every other install path (source checkout, `docker compose`)
> is unaffected. See [`docs/releasing.md`](https://github.com/NiravRVaghasiya/NetPro/blob/master/docs/releasing.md)
> for how releases are cut.

### From a source checkout

```bash
git clone https://github.com/NiravRVaghasiya/NetPro.git
cd NetPro
npm install
npm run build

node apps/cli/dist/index.js init
node apps/cli/dist/index.js serve        # API + built-in console at :3777
node apps/cli/dist/index.js --help       # the full 27-command surface
```

### Self-hosted, with PostgreSQL and the Web UI

```bash
git clone https://github.com/NiravRVaghasiya/NetPro.git && cd NetPro
cp .env.example .env          # set POSTGRES_PASSWORD (and auth mode)
docker compose up -d          # migrate → server → web + postgres:16-alpine
curl http://127.0.0.1:3777/api/health
```

One Docker image ships three roles: the standalone API server, the pure-client
web UI and the CLI the migration job runs. Postgres is not published to the host,
and both app ports bind to loopback unless you change them.

### Verify the download

```bash
curl -LO https://github.com/NiravRVaghasiya/NetPro/releases/download/v3.0.0/SHA256SUMS
shasum -a 256 -c SHA256SUMS
```

## What this release is

NetPro turns your **LinkedIn connections export** into a private, queryable
network database, then gives you the tools a paid social network hides behind a
subscription:

| Question | NetPro's answer |
| --- | --- |
| Who do I know, and who's gone quiet? | CRM contacts, relationship scores, dormancy analysis |
| How do I find a specific person? | Hybrid search — substring + full-text + optional semantic, fused with RRF |
| Who are the hubs, brokers and communities? | Louvain communities, degree & Brandes betweenness, components |
| Who can introduce me to *X*? | Pathfinder: ranked warm-intro chains **and the first ask to make** |
| Who should I reach out to, and what do I say? | Follow-up reminders + BYO-key AI drafting (drafts only — you send) |
| Where should I go next? | Event matcher and event recommendations from attendee lists |
| Is my writing landing? | Content tracker with metric snapshots and mentions |
| What are we collectively missing? | Skills gap analyzer against a target role |

### Highlights

**Own and query your data** — LinkedIn CSV import with dedup/merge, row-level
validation and a `--preview` mode that reports exactly which rows would be
skipped; CSV/JSON/vCard export; `netpro backup` / `netpro restore` with a
pre-restore safety copy; dual-dialect storage (SQLite in WAL mode by default,
PostgreSQL as a first-class option) with no `pgvector` requirement.

**Search that explains itself** — three arms (portable substring, keyword
full-text over the whole contact document via SQLite FTS5 / Postgres `tsvector`,
and an opt-in embedding arm) fused with reciprocal rank fusion (k=60), with
facets, pagination, sorting, filters and `--explain` match reasons. Configure
nothing and search still works: no index → substring, no key → no semantic arm,
provider down → keyword results with a stated reason.

**Network intelligence** — Louvain communities, degree and Brandes betweenness,
connected components, 12-month growth, industry/company diversity (Shannon
entropy), company clusters, dormant-ties reconnect list, and a BFS pathfinder
ranked by relationship strength (0.6 × weakest tie + 0.4 × mean hop strength).
Every edge carries `source`, `confidence` and a `status`; inferred edges land
**pending** and stay out of analysis until you confirm them.

**Keeping relationships alive** — per-contact interaction history with a
documented relationship score, follow-up reminders and due lists, and outreach
that stays yours: NetPro **drafts**, a human sends. No SMTP, no stored mailbox
credentials, no background sending. Campaigns produce messages you review and
record after sending them from your own mail client.

**Optional everything** — OpenAI/Anthropic (AI drafts), Hunter.io / People Data
Labs / Clearbit (enrichment) and embedding providers are bring-your-own-key
enhancements, kept in an AES-256-GCM encrypted workspace key vault (keys also
stay scoped in `~/.netpro`). With none configured, NetPro still imports, indexes,
searches, analyses, scores and reminds.

**The platform layer** — workspaces with owner > admin > member > viewer roles
(break-glass owner, last-owner guard, workspace-scoped queries, audit log),
plugins with strict manifests (capability allow-list, exact-host network
allow-list, install-disabled-by-default and a permissions review), a
checksummed self-hosted marketplace with hardened tarball extraction, and
outbound webhooks with an 18-event catalog, HMAC-SHA256 signatures, an SSRF
guard, exponential backoff and a delivery log.

**Three interfaces, one implementation** — 27 CLI commands, a local HTTP API
with a job model and SSE transport, and a ten-page web UI plus landing page.
Every long-running operation is one `@netpro/core` function → one job → one SSE
event stream → consumed by all three. Nothing is reimplemented in a UI layer, and
the web UI is a pure client: it opens no database and serves no API of its own.

## Verified for this release

The release commit passed the full CI gate — lint and typecheck on Node 20 and
22, unit tests, SQLite integration with the marketplace end-to-end smoke,
PostgreSQL integration against a real `postgres:16-alpine` (including the
release performance pass and the advisory-lock idempotency the Compose deploy
depends on), a build of all workspaces, the CLI process smoke, the server smoke
on **both** dialects, the standalone Web UI smoke, and the Docker image e2e that
runs the real deploy path (migrations via the shipped CLI, then server + web
against Postgres, including the token-mode auth boundary).

On the release commit, locally:

- **1,647 tests passing** across 135 test files — CLI 363, core 998, db 120,
  server 136, web 30 — with **60 PostgreSQL-backed tests skipped** because no
  `NETPRO_TEST_DATABASE_URL` was present; those run in CI against a live server.
- **15 migrations per dialect** (SQLite and PostgreSQL), **27 tables**, applying
  twice as a no-op.
- The packaged CLI bundle passes `npm run package:check`: self-contained
  `dist/index.js`, both migration sets, `netpro` bin, and only the two native
  drivers left external.

## Deliberately deferred

Documented, not forgotten — these are known and intentional gaps in v3.0.0:

- live event-discovery providers (the interface ships, disabled);
- a native `pgvector` column + ANN index (embeddings are portable JSON today);
- AI skills extraction as a default (it is opt-in per run);
- real SMTP delivery for campaigns — NetPro drafts, a human sends;
- `$EDITOR` draft review;
- cross-day viewer tracking or stranger deanonymisation (privacy by omission);
- a plugin sandbox — plugins run in-process, which is exactly why the manifest
  network allow-list and the review gate exist;
- a curated plugin store (the marketplace is a checksummed static index);
- a background webhook delivery worker and inbound webhook ingestion;
- web pages for the CLI-only capabilities;
- publishing to the npm registry (the unscoped name is taken; see
  [`docs/releasing.md`](https://github.com/NiravRVaghasiya/NetPro/blob/master/docs/releasing.md)).
